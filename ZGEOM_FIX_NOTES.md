# Правки окна piHPSDR (октябрь 2026)

## Проблемы (исходное состояние)
1. Окно запускалось в полноэкранном режиме (fullscreen_on_monitor):
   без рамки, поверх всех окон, нельзя было подвинуть.
2. Окно растягивалось мышкой только наружу — внутрь не сжималось.
   Причина: контент лежал в GtkFixed, который навязывает окну
   минимальный размер по самому большому виджету, поэтому события
   сжатия до программы не доходили.
3. При старте (пока висел диалог выбора устройства) окно дёргалось:
   замер рамки проходил до запуска радио и запоминал неверный запас
   (pad), отсюда прыжки 884x581 -> 832x554 -> 1134x554.

## Что сделано
1. GtkFixed заменён на GtkLayout в src/radio.c, src/sliders.c,
   src/toolbar.c:
   - тип указателя: GtkFixed *fixed -> GtkWidget *fixed
   - создание: gtk_fixed_new() -> gtk_layout_new(NULL, NULL)
   - размещение: gtk_fixed_put -> gtk_layout_put
   - перемещение: gtk_fixed_move -> gtk_layout_move
   GtkLayout не навязывает окну минимальный размер, поэтому окно
   сжимается мышкой в обе стороны.
2. В src/main.c (блок ZGEOM apply) добавлены вызовы при каждой
   перетройке:
   - gtk_window_set_resizable(..., TRUE) — растяжка мышкой
   - gtk_window_unfullscreen(...) — возврат рамки и перемещения
   - gtk_window_set_keep_above(..., FALSE) — не поверх всех окон

## Известные остатки
- Рамка окна по-прежнему отсутствует при старте: снятие fullscreen
  срабатывает только при первой перетройке, а не при создании окна.
  Для возврата рамки нужно добавить unfullscreen при создании окна
  в main.c.

## Файлы патчей (в /tmp, после перезагрузки пропадают)
