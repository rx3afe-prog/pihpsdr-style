ПАМЯТКА ПО GIT — репозиторий piHPSDR-style
================================================

GitHub: https://github.com/rx3afe-prog/pihpsdr-style
Логин:  rx3afe-prog
Папка:  ~/piHPSDR-style

КАК СОХРАНИТЬ РАБОТУ (когда что-то поправил в коде):

    git status              <- проверить, что изменено
    git add -A              <- собрать все изменения
    git commit -m "что сделал"  <- сохранить с подписью (своими словами!)
    git push                <- отправить на GitHub

Если git status говорит "working tree clean" — сохранять нечего,
команды вводить не нужно.

КОГДА ПРОЕКТ СНОВА РАБОТАЕТ — СТАВИТЬ МЕТКУ (тег):

    git tag v2-working      <- любое новое имя, старые заняты:
                               working-good, shtatka-gotova, zgeom-fix
    git push --tags         <- отправить метку в облако

ПОЛЬЗОВАТЕЛЬ И ПАРОЛЬ ДЛЯ GIT:

    Username: rx3afe-prog
    Password: токен с сайта github.com/settings/tokens
              (галочка repo, срок — сколько укажешь)
    НЕ пароль от сайта GitHub! Токен начинается с ghp_

ВАЖНЫЕ ПРАВИЛА (выучено тяжёлым путём, 27 октября 2026):

1. Токен нужен с галочкой "repo" (полный доступ к репозиториям),
   НЕ "public_repo" — иначе приватный репозиторий не откроется.
2. Токен НЕ светить в чатах и переписке. Если засветился —
   удалить на github.com/settings/tokens и сделать новый.
3. git push --set-upstream - это когда git сам просит привязать ветку.
   В норме достаточно "git push", ветка уже привязана.
4. git status - безобидная команда, ничего не меняет,
   всегда говорит, что происходит. Не помнишь - набирай её.
5. Перед любыми опытами с репозиторием - сначала git status,
   потом действовать.

ЕСЛИ ЧТО-ТО ЗАШИПЕЛО:

- "Invalid username or token" -> в команде не настоящий токен
  или он без галочки repo.
- "Could not resolve host: ..." -> команда введена частично,
  набирай целиком одной строкой.
- "nothing to commit" -> всё уже сохранено, это не ошибка.
